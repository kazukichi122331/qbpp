# makespan 型の A100 計測：n40w20 を目標値なしで 30 秒（2026-09-29）

実行日: 2026-09-29 16:10 開始  
実行: [scripts/run_time_makespan_a100.sh](../scripts/run_time_makespan_a100.sh)（git commit `112d558`、`TARGET=none`）  
環境: a100x8 / NVIDIA A100 80GB PCIe（`CUDA_VISIBLE_DEVICES=7`）/ `qbpp.ABS3Solver`  
定式化: [src/time_makespan.py](../src/time_makespan.py)（目的関数 = 帰着時刻）  
条件: n = 40、w = 20、インスタンスは Dumas の `n40w20.001`。**10 回**（seed 1〜10）、制限時間 **30 秒**、実行ごとに 60 秒の間隔。**目標値を与えず**、全実行を制限時間まで走らせた

前夜の計測（[time_a100_results_0928_rerun.md](time_a100_results_0928_rerun.md)）では、makespan の n40w20 で最小エネルギー 524 が 1 回しか出ず、平均 TTS も 12.29 秒と他の顧客数より長かった。この計測では目標値（525）による打ち切りをなくし、30 秒のあいだにどこまで下がるかを見た。

生データ: [lab_results/time_makespan_a100_n40w20_notarget_09291610/](../lab_results/time_makespan_a100_n40w20_notarget_09291610/)

## 0. 要点

- **10 回とも実行可能で、制約違反は 0。** 検算の帰着時刻は 525 が 7 回、526 が 3 回。
- **前夜に 1 回だけ出た 524（検算 523）は、30 秒を使い切っても一度も出なかった。** 最小エネルギーは 525 止まり。
- 目標値のあった前夜は、エネルギー 525 以下が出た時点で打ち切っていた。そのため「最良解が 1 回だけ」だったのは、524 が出にくい解だからで、打ち切りのせいで見落としたわけではない。
- 総移動時間は 4 回が 500 で、Dumas の既知最良値（総移動時間 500）と同じ値。帰着時刻 525 の解は、移動 500〜507 のいくつかのツアーに分かれている。

## 2. 検算値で見た結果

「実行可能」は、復元したツアーを最早開始で辿り直して全顧客・時間枠・帰着期限を満たすもの。検算値はそのときの帰着時刻（ログの `return` 行）。

|合計時間|目標値（参考）|実行可能|目標値以下|平均値（検算）|最良値（検算）|
|---|---|---|---|---|---|
|顧客数: 40|525|10/10|7/10|525.3|525 (7)|

目標値 525 は、既知最良ツアー（総移動時間 500）を最早開始で辿ったときの帰着時刻。この計測では打ち切りには使っていない。

## 3. 前夜の計測（目標値あり）との比較

前夜の値は [time_a100_results_0928_rerun.md](time_a100_results_0928_rerun.md) の n40w20（`TARGET=best`、目標 525）。

| 項目 | 前夜（目標値あり） | 今回（目標値なし） |
|---|---|---|
| 打ち切り | エネルギー ≤ 525 で終了 | 30 秒まで探索 |
| 平均エネルギー | 525.2 | 525.5 |
| 最小エネルギー(回数) | 524 (1) | 525 (5) |
| 検算値 ≤ 525 | 10/10 | 7/10 |
| 平均値（検算） | 524.8 | 525.3 |
| 最良値（検算） | **523** (1) | 525 (7) |
| 平均TTS | 12.29 | 8.01 |

- **523 は前夜の seed 4 の 1 回だけ。** 0.66 秒で見つかっており、ツアーは `… 22, 21, 9, 19, 26, 11, 29 …` の並び（総移動時間 501）。今回の 10 回はこの並びに一度も入らなかった。
- **前夜の平均 TTS 12.29 秒は、目標値 525 に届くまでの時間。** 今回も 525 を出した 5 回の平均は 11.27 秒で、ほぼ同じ。n40w20 では 525 に届くまでに 10 秒前後かかる、という傾向は打ち切りの有無によらない。
- 検算値 ≤ 525 は 10/10 → 7/10 に減った。seed は同じ 1〜10 だが、前夜と今回で結果は一致しておらず（GPU 上の探索は同じ seed でも再現しない）、この差は 10 回ずつの試行のばらつきの範囲と見るべき。今回の 526 の 3 回は、30 秒のあいだに 525 へ降りられなかった実行。

## 4. 所見

- **n40w20 の makespan では、525 の解は比較的見つかりやすいが、それより良い 523 は 30 秒ではまれにしか出ない。** 前夜の「最良解が 1 回だけ」は、目標値による打ち切りではなく、解そのものの出にくさによる。
- **525 の解が多数ある平らな地形になっている。** 総移動時間が 500〜507 と異なる複数のツアーが同じ帰着時刻 525 を与える。帰着時刻だけを目的関数にしていると、これらの間でエネルギー差がつかず、523 の方向へ誘導する勾配が弱いと考えられる。
- 523 の出現頻度を見積もるには、制限時間を延ばす（例: 300 秒）か、試行回数を増やす計測が必要。
