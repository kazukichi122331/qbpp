# 在圏型 制約B の係数の付け方の比較（n60w20.001）

- スクリプト: `src/tsptw/time_occupancy_weights.py`（制約B の係数だけを差し替える実験版）
- 一括実行: `scripts/sh/occupancy_weights.sh`（`SET=1/2/3`）
- 条件: n60w20.001、30 秒、target = 551（既知最良値）、ABS3、手元機（WSL, RTX 4060 Ti）
- 到達 = 検算（最早開始で辿り直し）で実行可能かつ travel = 551
- 結果フォルダ
  - 第 1 弾 `lab_results/0930-1734_occupancy_weights_n60w20_wsl`
  - 第 2 弾 `lab_results/0930-1833_occupancy_weights_n60w20_set2_wsl`
  - 確認 `lab_results/0930-1903_occupancy_weights_n60w20_set3_wsl`（20 回）

## 用語（この実験で作った言葉）

| 用語 | 意味 |
|---|---|
| 禁止組 | 制約B の 1 項 `o[t,u]*o[t',v]`。u に時刻 t、v に時刻 t' に居ることが両立しない組 |
| 向き付き組 | 禁止組を「u が先・v が後」の向きで見たもの。t'=t の組は両向きから禁止されるので 2 つ重なる（現行で係数が 2 倍になる理由）。係数は向き付き組ごとに決めて足す |
| 不足時間 δ | 向き付き組が実行可能になるまで t' を後ろへずらす量 `t + gap(u,v) - t'` |
| ペア | 頂点の対 {u,v}。禁止組を頂点の対で束ねた単位 |
| 順序確定ペア | 時間窓から片方の順でしか間に合わないペア（`svc[v] + gap(v,u) > ohi[u]` なら v→u は不可）。n60w20.001 で衝突項を持つペアのうち 156 組（うち 101 組は前処理の L<E で既に分かる）。両順ありうるのは 70 組 |
| 逆順組 | 順序確定ペアで、ありえない向きの向き付き組。6407 個（向き付き組 47572 の 13%） |
| 発側待機組 | 発側が待機スロットの向き付き組（`--slim` が落とす冗長な組） |
| 次数 | ある変数が現れる禁止組の数 |
| 学習ラウンド | 制限時間を R 等分し、1 回解くごとに破れた禁止組を含むペア全体の係数を `--grow` 倍して解き直すこと。既定は直前の解を hint（初期解）に渡す |
| 顧客落ち | 制約A が破れ、顧客を 1 人も訪問しない解。罰 P_CUST=249 を払えばその顧客の衝突がすべて消える |

## 何が起きていたか（現行 = 一律係数 125）

失敗はほぼすべて **同じペア {27, 39} の衝突 1 個** だった（energy 666 = objective 541 + 125）。
27 の窓 [263,284]、39 の窓 [273,300]、c = 12 で、39 の最早 273 + 12 = 285 > 284 なので
**27→39 の順しか実行可能でない**（順序確定ペア）。それなのに半数は 39 を先に置く逆順組を破っていた。

罰そのものは足りている（666 > 551）。問題は罰の大小ではなく、この谷に早く（1〜3 秒で）落ちて抜けられないこと。

## 第 1 弾（10 回）

| 設定 | 内容 | 到達 | 主な失敗 |
|---|---|---|---|
| uniform | 現行（一律 2·max_c+1 = 125） | 3 | {27,39} の衝突 1 個 |
| scale0.5 / scale2 | 制約B 全体 ×0.5 / ×2 | 0 / 0 | ×0.5: 衝突 2〜3 個、×2: 顧客落ち |
| delta | 2·min(δ,max_c)+1（浅い違反ほど軽い） | 0 | 衝突 2〜5 個（罰 29 で 32 稼ぐ。罰不足） |
| pair | 2·min(gap(u,v),max_c)+1 | 0 | 衝突 2〜4 個 |
| waitsrc0.5 | 発側待機組だけ ×0.5 | 3 | uniform と同じ |
| degree | 次数で正規化（下限 3、上限 2P） | 2 | 違反 0 だが 552〜555 で停滞 |
| rev4 | 逆順組 ×4 | 4 | 逆順の違反は消え、{27,39} を正しい順で詰めすぎ |
| cust0.5 / cust2 | 制約A ×0.5 / ×2 | 0 / 1 | ×0.5: 顧客落ち、×2: 衝突 |
| learn3 / learn6 | 学習ラウンド 3×4 倍 / 6×2 倍 | 5 / 5 | 係数が育ちすぎて顧客落ち |

読み取れること:

- **制約B を一律に下げると衝突に、上げると顧客落ちに違反が逃げる**。全体の倍率では直らず、制約A との釣り合いで上限が決まる。
- 項ごとの「最悪の得」に合わせて下げる δ・pair は罰不足になる。1 つの衝突で稼げる量が δ や gap より大きい場合があり、δ に比例した見積もりは楽観的すぎた。
- 破れやすいのは特定のペア。そこだけ上げる（rev、learn）は効く。

## 確認（20 回, seed 1〜20）

| 設定 | 到達 | 実行可能 | 違反あり | 到達時の平均 TTS |
|---|---|---|---|---|
| uniform（現行） | 5/20 | 11/20 | 13/20 | 13.3 s |
| forced2_rev2 | 12/20 | 20/20 | 0/20 | 8.9 s |
| **forced2_rev4** | **15/20** | **20/20** | **0/20** | **7.6 s** |
| learn6cap2 | 15/20 | 18/20 | 1/20（顧客落ち） | 12.2 s |
| rev4_learn6cap2 | 15/20 | 17/20 | 1/20（顧客落ち） | 10.0 s |

（「実行可能」は検算の feasible。衝突を抱えていても検算では通る回があるので、違反ありと実行可能の合計は 20 にならない）

## 結論

- 最良は **順序確定ペア ×2 + 逆順組にはさらに ×4**（逆順組は実質 ×8 = 1000）。到達 5/20 → 15/20 で、20 回とも制約違反がなかった。
  追加の探索ラウンドは要らず、係数は前処理（時間窓と gap）だけで決まる。未到達の 5 回は 552〜553 の実行可能な局所解。
- 学習ラウンドも同じ 15/20 だが、上限（`--cap`）を付けないと顧客落ちに逃げる。インスタンスについて事前に何も知らなくてよいのが利点。
- 一律の倍率、δ・gap に比例した縮小、発側待機組の縮小は効かなかった。

## 注意と次の候補

- 1 インスタンス・1 機種の結果。n60w20.001 は順序確定ペア {27,39} という分かりやすい罠を持つので、他のインスタンスで同じ効き方をするかは未確認。
- 順序確定ペアは本来、前処理で定義域を削れる（27→39 が確定なら `svc[39] >= svc[27] + 12`）。
  `arrival_lower_bounds` は L[u] < E[v] しか見ていないので、この判定を不動点に足せば、罰を重くしなくても逆順組そのものを消せる。係数調整の次に試す価値がある。
- 手元の GPU は乱数が再現しない（同じ seed でも結果が変わる）ので、10 回の差 ±2 程度は誤差の範囲。

# 続き: n200w20.001 と n60w100.001（2026-09-30〜10-01）

- 条件: 手元機（WSL, RTX 4060 Ti）、target = 既知最良値（n200w20: 1019、n60w100: 515）
- 値は検算した travel（最早開始で辿り直したもの）。ギャップ = (travel − 最良) / 最良
- 比較の基準（現行の一律係数、同じ手元機で 300 秒）: `lab_results/archive/0929-1203_occupancy_until_target_wsl`
  - n200w20: 実行可能 1/9（1020, 0.1%）。ほかは衝突 1〜2 個
  - n60w100: 実行可能 1/8（532, 3.3%）。ほかは衝突 1〜2 個

## 追加した用語

| 用語 | 意味 |
|---|---|
| 顧客ごとの学習（`--learn-cust`） | 学習ラウンドで、制約A が破れた（落ちた・二重訪問の）顧客の係数も顧客ごとに `--grow` 倍する |
| 減衰（`--decay d`） | 学習で上げた係数のうち、そのラウンドで破れなかったものを d 倍して初期値へ戻す（初期値より下げない） |
| 最良再開（`--hint-best`） | 実行可能解が見つかっていれば、次のラウンドの初期解をその最良解にする |
| 詰め残し | 実行可能解で、モデル上の objective が検算 travel より大きいこと。ツアーの順は同じで、各頂点の時刻を前に詰め切れていない |
| learnA | `--rounds 10 --grow 2 --cap 4 --learn-cust`（衝突と制約A の両方を学習、上限は初期の 4 倍） |

## 結果（300 秒 × 3 回。120 秒の探りは本文末尾）

| 設定 | n200w20 実行可能 | n200w20 travel | n60w100 実行可能 | n60w100 travel |
|---|---|---|---|---|
| 現行（基準, 300 秒） | 1/9 | 1020 | 1/8 | 532 |
| f2r4（n60w20 の最良） | 0/3（全部顧客落ち） | – | 1/3 | 521 |
| learnA | **3/3** | 1026〜1029 | **3/3** | 527〜537 |
| rev4_learnA | 1/3 | 1029 | 3/3 | 527〜541 |
| learnA_decay（減衰 0.7） | 2/3 | 1025〜1038 | 3/3 | 526〜532 |
| learnA_best（最良再開） | 2/3 | 1026〜1028 | 3/3 | 532〜535 |
| learnA_decay_best | 2/3 | 1027 | 2/3 | 533 |
| **learnA_swap**（+ ABS3 auto_swap） | **3/3** | 1025〜1044 | **3/3** | **523〜528** |
| learnA_half（罰を全部 ×0.5） | 2/3 | 1032〜1034 | 3/3 | 530〜539 |

どの設定も **ギャップ 0% には届かなかった**（最良: n200w20 1025 = 0.6%、n60w100 521 = 1.2%）。

120 秒 × 3 回の探り（`lab_results/0930-2104_…_n200w20_t120_set4_wsl`、`0930-2147_…_n60w100_t120_set4_wsl`）:
一律・rev4・f2r4 に制約A ×1.1・全体 ×0.5・learn6cap2・rev4_learn6cap2・f2r4 + auto_swap。
実行可能はどれも 0〜3/3 で、300 秒の結果と同じ傾向（学習系が安定、静的な重みは顧客落ちか衝突）。
f2r4 に制約A ×2、×4 も試したが（診断実行）、違反が衝突側に戻って 12 回中 1 回しか実行可能にならなかった。

## 読み取れること

1. **n60w20 で効いた静的な重み（順序確定ペア）は大きいインスタンスに移らない。**
   n200w20 では、順序確定ペアの項（係数 242）が顧客 1 人の罰（241）を上回り、違反が顧客落ちに逃げる。
   制約A を上げると衝突に戻る。n60w100 は時間窓が広く、破れるペア（21-11、23-58 など）の大半は順序が確定していない。
2. **違反は同じ少数の頂点のあいだで、衝突と顧客落ちを行き来する**（n200w20 では 98・148・153・161・170 のまわり）。
   どちらか一方の係数だけ上げても、もう一方に移るだけ。
3. **両方を学習する learnA で、実行可能性はほぼ解決した**（基準の約 1 割 → 3/3）。事前の構造知識も要らない。
4. **ギャップが残るのは、主に詰め残しのせい。** 実行可能解の objective は travel より 3〜42 大きい。
   時刻を 1 つ前に詰めるには one-hot の 2 ビットを同時に反転する必要があり、途中で制約A の壁（学習で最大 4 倍）を越える。
   auto_swap（one-hot を保つ 2 ビット同時反転）で n60w100 が 523〜528 に安定したのはこの見立てと合う。
5. 減衰・最良再開・全体を弱める、はどれも learnA を明確には上回らなかった（3 回ずつなので差は誤差の範囲）。

## 係数以外で次に効きそうなこと

- **順序確定ペアを前処理で定義域に反映する。** `arrival_lower_bounds` は L[u] < E[v] しか見ていない。
  「v→u では間に合わない」も判定に入れれば、逆順組が項ごと消え、変数も減る。
- **詰め残しを後処理で取る。** 評価は既に検算 travel で行っているので、ツアーの順だけ使えば詰め残しは値に影響しない。
  ギャップは詰め残しではなく、ツアーの順そのものが最良と違うことから来ている。ただし詰め残しがあると、
  ソルバのエネルギーが高く出て、順序を入れ替える動きが見えにくくなっている可能性がある。
- **時間を延ばす / A100 で回す。** 学習系の 300 秒の実行では、最良解の発見（TTS）が 240 秒以降だった回が 36 回中 11 回あり、まだ改善が続いている。
