# `time_makespan_multi_leq.py` の解説：複数車両 min-max を不等式制約で書く時間展開型 QUBO

対象: [src/mtsptw/time_makespan_multi_leq.py](../src/mtsptw/time_makespan_multi_leq.py)
補助: [src/mtsptw/mtsptwlib.py](../src/mtsptw/mtsptwlib.py)（`load_minstance` / `make_gap` / `make_vars_multi` / `vehicle_view` / `recover_routes`）、[src/tsptwlib/timeindex.py](../src/tsptwlib/timeindex.py)（`conflict_terms`）
兄弟版: [src/mtsptw/time_makespan_multi.py](../src/mtsptw/time_makespan_multi.py)（同じ問題を one-hot の Z で書いた版）

---

## 0. 要点

- **解く問題**: 車両 m 台の時間枠付き巡回問題（mTSPTW）で、**全車両の帰着時刻の最大値（makespan）を最小化**する（min-max）。
- **変数**: `x[t][i][v] = 1` ⇔ 車両 v が頂点 i のサービスを時刻 t に開始する。これに加えて、最大帰着時刻を表す**整数変数 `Z` を 1 個**だけ持つ。
- **制約**: (A) 各顧客をちょうど 1 回、各車両の帰着をちょうど 1 回。(B) 同じ車両の中で、移動時間より短い間隔で 2 頂点を訪れるのを禁止。(C) 各車両について `ret_v <= Z`。
- **目的関数**: `Z` そのもの。最小化すると `Z = max_v ret_v` に落ち着く。
- **なぜこれで解けるか**: ペナルティ 0 の割り当てと mTSPTW の実行可能解が対応し、重み `L[0] + 1` により制約を破った割り当てはどれも実行可能解よりエネルギーが高くなる（[3.5 節](#35-なぜ-abc-で-mtsptw-を表せるのか)）。
- **one-hot 版との違い**: `Z` を 0/1 の one-hot で持たず、QUBO++ のネイティブ整数変数と不等式制約 `qbpp.cons(..., between=(0, None))` で書く。スラック変数も one-hot 変数も要らない。
- **実験**: Dumas の 4〜5 インスタンス、2 台（RTX 4060 Ti）と 3 台（A100）で各 10 回・30 秒回すと、**全実行が実行可能で、すべて Z の下界 `z_lo` に到達（= 最適）** した。ただし今回のインスタンスでは下界が自明に達成できるので、探索力の比較にはなっていない（[8 節](#8-実験結果)）。

## 1. 解きたい問題: mTSPTW（min-max）

- デポ（番号 0）から **m 台の同じ車両**が時刻 0 に出発する。
- 顧客 1..N を、**どれか 1 台がちょうど 1 回**訪問する。
- 顧客 i のサービス開始時刻は時間枠 `[E[i], L[i]]` に入っていなければならない（早く着いたら待ってよい）。
- 全車両が時刻 `L[0]` までにデポへ戻る。顧客を 1 人も回らない車両（空車）があってもよい。
- 目的は **`max_v（車両 v の帰着時刻）` の最小化**。「最後の 1 台が戻ってくる時刻をできるだけ早くしたい」という問題で、総移動時間は目的に入らない。

インスタンスは Dumas のベンチマーク（サービス時間 0、距離・時間は整数）。

### 頂点番号

時間展開型では「出発」と「帰着」を別の頂点にしておくと扱いやすいので、デポを 2 つに分ける（`load_minstance`）。

| 番号 | 意味 | 変数 |
|---|---|---|
| 0 | 出発デポ | なし（時刻 0 に出発で固定） |
| 1..N | 顧客 | `x[t][i][v]` |
| N+1 | 帰着デポ | `x[t][N+1][v]`（車両ごとに 1 回） |

距離行列は列 N+1 と行 N+1 を列 0・行 0 のコピーとして足す。したがって `c[i][N+1] = c[i][0]`。

---

## 2. 変数と時刻ドメイン

```
x[t][i][v] = 1  ⇔  車両 v が頂点 i のサービスを時刻 t に開始する
```

時刻 t は整数で、各頂点で**ありうる時刻だけ**に変数を作る（ドメインを絞る）。

| 頂点 | 下限 `lo[i]` | 上限 `hi[i]` | 理由 |
|---|---|---|---|
| 顧客 i | `max(E[i], c[0][i])` | `min(L[i], L[0] − c[i][N+1])` | デポから直行しても `c[0][i]` より前には着けない／そこからすぐ帰っても `L[0]` に間に合う必要がある |
| 帰着デポ N+1 | 0 | `L[0]` | 0 は空車（どこも回らずに「帰着」する）を表す |

ドメインは車両によらないので、変数の数は `m × (Σ_i (hi[i] − lo[i] + 1) + L[0] + 1)` になる。これに `Z` が 1 個加わる。

## 3. 制約

### 3.1 制約 A: ちょうど 1 回（`once_constraint`）

制約 A は 2 種類の「ちょうど 1 個だけ 1」（one-hot 制約）からなる。

```
A-1 各顧客 i:      Σ_v Σ_{t=lo[i]}^{hi[i]} x[t][i][v]  = 1     （誰か 1 台が、1 回だけ回る）
A-2 各車両 v:      Σ_{t=0}^{L[0]}     x[t][N+1][v]    = 1     （各車両は 1 回だけ帰着する）
```

コードでは `qbpp.sum(...) == 1` を顧客ごと・車両ごとに作って足し合わせ（`once_cust` + `once_end`）、`ONCE_P * qbpp.cons(once_constraint)` でペナルティにしている。

#### A-1: 顧客の one-hot — 「どの車両が」と「いつ」を 1 本でまとめて決める

顧客 i の変数は、車両 v と時刻 t の 2 軸に並んでいる。5 節の例の顧客 A なら、車両 2 台 × 時刻 6〜30 の 25 通りで 50 個ある。

```
          t = 6   7   8  ...  30
車両 0:    x   x   x  ...   x
車両 1:    x   x   x  ...   x
           └───── この 50 個のうち、ちょうど 1 個だけが 1 ─────┘
```

この 50 個の和を 1 にすることで、次の 3 つが同時に表される。

1. **訪問漏れがない**（和が 0 でない）
2. **重複訪問がない**（同じ車両が 2 回、あるいは 2 台がそれぞれ 1 回、どちらも和が 2 以上になる）
3. **担当車両が 1 台に決まる**（1 になった変数の v がその顧客の担当車両）

「車両の割り当て」と「訪問時刻」を別々の変数で持たず、1 本の one-hot で同時に決めるのがこの定式化の特徴である。車両ごとに `Σ_t x[t][i][v] = 1` を課してしまうと「全車両が顧客 i を回る」ことになるので、**和は車両についても取る**必要がある。

また、変数は時間枠の内側 `[lo[i], hi[i]]` にしか作っていない（2 節）。したがって A-1 を満たした時点で、**開始時刻は自動的に時間枠に入る**。時間枠のための制約は別に要らない。

#### A-2: 帰着デポの one-hot — 車両ごとに帰着時刻を 1 つに決める

帰着デポ N+1 は、顧客と違って**車両ごとに 1 回**帰着する。こちらは車両ごとに和を取る。

- 和が 1 なので、`ret_v = Σ_t t · x[t][N+1][v]` が「1 になった変数の時刻」そのものになる。制約 C はこの式を使うので、A-2 は **C が意味を持つための前提**である。
- 時刻 0 もドメインに入っているのは**空車**のため。顧客を 1 人も回らない車両は時刻 0 に「帰着」できる。顧客を 1 人でも回る車両は、制約 B（帰着の後に顧客は来られない）により時刻 0 には帰着できない。
- 出発デポ 0 は時刻 0 に固定なので変数を持たず、one-hot も要らない。

#### ペナルティ `(Σ − 1)²` の中身

1 になっている変数の個数を k とすると、ペナルティは `ONCE_P × (k − 1)²` で、

| k（1 の個数） | 0 | 1 | 2 | 3 |
|---|---:|---:|---:|---:|
| `(k − 1)²` | 1 | **0** | 1 | 4 |
| 意味 | 訪問漏れ／帰着なし | 正常 | 重複 | 重複 |

となり、ちょうど 1 のときだけ 0 になる。0/1 変数では `x² = x` なので、展開すると

```
(Σ_a x_a − 1)² = 1 − Σ_a x_a + 2 Σ_{a<b} x_a x_b
```

という QUBO になる。**1 次の項 `−x_a` は「どれか 1 つを立てる」ことへのごほうび**、**2 次の項 `2 x_a x_b` は「2 つ同時に立てる」ことへの罰**と読める。

重みは `ONCE_P = L[0] + 1`。顧客を 1 人回らずに済ませると最大帰着時刻が下がって目的関数が得をするが、その得は高々 `L[0]`（Z の上限）なので、`k = 0` の罰 `L[0] + 1` の方が必ず大きい（詳しくは [3.5 節](#35-なぜ-abc-で-mtsptw-を表せるのか)）。

#### 制約 B との役割分担

制約 B の衝突項は**異なる頂点の組**（`u ≠ w`）にしか作らない。したがって「同じ車両が顧客 i を時刻 10 と時刻 20 に 2 回回る」は B では罰せられず、**A-1 だけが防いでいる**。逆に A は時刻の前後関係を何も見ないので、移動時間の整合は B に任せている。

### 3.2 制約 B: 同じ車両の中の衝突禁止（`conflict_constraint`）

同じ車両 v の中で、頂点 u を時刻 t、頂点 w を時刻 t' に開始したとする。`t ≤ t'`（u の方が先）なら、u から w へ移動する時間がかかるので

```
t' ≥ t + gap(u, w)      gap(u, w) = s[u] + c[u][w]   （Dumas は s = 0 なので c[u][w]）
```

でなければならない。そこで、これを破る組をすべて禁止する。

```
ペナルティ項  x[t][u][v] · x[t'][w][v]      （t ≤ t' < t + gap(u, w)）
```

- 帰着デポの後には何も来ないので `gap(N+1, ·) = ∞`。「帰着した後に顧客を回る」はすべて禁止される。
- `t = t'` も禁止に含まれるので、同じ車両が同時刻に 2 か所で開始することもない（`gap = 0` の同一地点ペアだけは例外）。
- 項は**車両ごとに独立**に作る（`vehicle_view` で車両 v の変数だけを抜き出して `conflict_terms` に渡す）。違う車両どうしは同時刻に別の場所にいてよいので、車両をまたぐ項はない。
- 隣り合う訪問だけでなく**全ペア**に課す。時間展開型では「ツアー上で隣」を表す変数がないためである。三角不等式が成り立てば、全ペアに課しても実行可能なツアーは切られない。Dumas の距離行列は丸めのせいで三角不等式がわずかに破れる箇所があり、その意味でこの定式化は厳密にはごく少しだけ狭い（詳細は `conflict_terms` の docstring）。

ペナルティは `CONF_P × Σ（禁止ペアの積）`。

制約 A と B を満たせば、各車両について「時刻順に並べた訪問列」がそのまま実行可能なルートになる。出発デポからの移動は顧客のドメイン下限 `c[0][i]` で、帰着デポへの移動は (u, N+1) の衝突項で保証される。

### 3.3 制約 C と目的関数: `ret_v <= Z`（`zmax_constraint`）— この版の中心

車両 v の帰着時刻は、帰着デポ変数から線形に読める。

```
ret_v = Σ_t t · x[t][N+1][v]          （制約 A により 1 つだけ 1 なので、その時刻）
```

最大値 `max_v ret_v` は QUBO の 2 次式で直接は書けない。そこで**上から押さえる変数 Z**を用意し、

```
最小化   Z
制約     ret_v ≤ Z     （全車両 v）
```

とする。これは min-max を線形計画で書くときの定番の変形と同じである。

- Z を実際の最大帰着時刻より**下げる**と、最も遅い車両で `ret_v ≤ Z` が破れて罰せられる。
- Z を**上げる**と目的関数がそのまま増える。
- したがって最小化すると `Z = max_v ret_v` になる。

コードでは次のように書く。

```python
Z = qbpp.var("Z", integer=(z_lo, depot_l))        # ネイティブ整数変数
for v in veh:
    body = qbpp.expr() + Z
    for t in range(lo[end], hi[end] + 1):
        body -= t * x[t, end, v]                   # body = Z − ret_v
    zmax_constraint += qbpp.cons(body, between=(0, None))   # body ≥ 0
objective = qbpp.expr() + Z
```

`qbpp.cons(body, between=(0, None))` は**スラック変数を作らない宣言型の不等式制約**で、ソルバが `max(0, −body)²` を直接評価する。つまり違反量 `d = ret_v − Z` に対してペナルティは

```
ZMAX_P × Σ_v max(0, ret_v − Z)²
```

になる（`d ≤ 0` なら 0、`d ≥ 1` なら `d²` で増える）。

#### Z の定義域 `[z_lo, L[0]]`

```
z_lo = max_i (lo[i] + s[i] + c[i][N+1])
```

顧客 i はどれかの車両が回るので、その車両は「i を最も早く始めて、すぐ帰る」より早くは戻れない。したがって最大帰着時刻は必ず `z_lo` 以上で、定義域をここまで削っても最適解は失われない。**この値は最適値の下界**でもあり、解がここに届けば最適と判定できる（[8 節](#8-実験結果)で使う）。

#### ペナルティの重み

```
ONCE_P = CONF_P = ZMAX_P = L[0] + 1
```

- 目的関数 `Z` は `L[0]` 以下なので、制約 A・B を 1 単位破って得する目的関数の量は高々 `L[0]`。重み `L[0] + 1` なら破る方が必ず損になる。
- 制約 C は、Z を d だけ下げて得する量が d、罰が `ZMAX_P · d² ≥ ZMAX_P · d` なので、本来は `ZMAX_P > 1` で足りる。他の制約と尺度をそろえるために同じ値にしている。

### 3.4 全体のエネルギー

```
f = Z
  + (L[0]+1) · [ Σ_i (Σ_{v,t} x[t][i][v] − 1)²  +  Σ_v (Σ_t x[t][N+1][v] − 1)² ]      … A
  + (L[0]+1) · Σ_v Σ_{u≠w} Σ_{t ≤ t' < t+gap(u,w)} x[t][u][v] · x[t'][w][v]           … B
  + (L[0]+1) · Σ_v max(0, Σ_t t·x[t][N+1][v] − Z)²                                     … C
```

制約をすべて満たす解では `f = Z = max_v ret_v`。

### 3.5 なぜ A・B・C で mTSPTW を表せるのか

#### 各制約はなぜ必要か（外すと何が起きるか）

1 つずつ外すと、エネルギー最小の解が mTSPTW の解ではなくなる。

| 外す制約 | 最小エネルギーの解 | 何が壊れるか |
|---|---|---|
| A-1（顧客 one-hot） | x をすべて 0 にし、Z = `z_lo` | 顧客を 1 人も回らない解が最良になる。罰がなければ「回らない」のが一番得 |
| A-2（帰着 one-hot） | 使う車両の帰着変数をすべて 0 にする | `ret_v = 0` になり C が素通しになる。「帰らない車両」で最大帰着時刻をごまかせる。2 個立てると `ret_v` が 2 つの時刻の和になり、意味を失う |
| B（衝突禁止） | 全顧客を好きな車両に時刻 `lo[i]` で割り当て、帰着はすべて 0、Z = `z_lo` | 移動時間を無視して瞬間移動でき、1 台が同時刻に何か所でも回れる。ルートとして成立しない |
| C（`ret_v ≤ Z`） | 実行可能なルートなら何でもよく、Z = `z_lo` | Z がルートと無関係になり、どの実行可能解もエネルギー `z_lo` で同点。makespan を最小化しなくなる |

まとめると、**A が「誰が・何回」、B が「どの順で・物理的に間に合うか」、C が「何を最小化するか」** を受け持ち、どれが欠けても問題が変わってしまう。

#### A・B・C を満たす解 ⇔ mTSPTW の実行可能解

ペナルティがすべて 0 の割り当て（x, Z）と、mTSPTW の実行可能解は、次の意味で対応する。

**(1) ペナルティ 0 の割り当て → 実行可能なルート**

1. A-1 により、各顧客はちょうど 1 台に割り当てられ、開始時刻 `t_i` が 1 つ決まる。顧客が車両ごとに分割される。
2. 各車両 v の担当顧客を `t_i` の小さい順に並べ、`0 → i_1 → i_2 → … → i_k → N+1` をその車両のルートとする。
3. 隣り合う `i_j → i_{j+1}` は、B により `t_{i_{j+1}} ≥ t_{i_j} + c[i_j][i_{j+1}]` を満たす。つまり**前の顧客を始めてから移動しても間に合う**。早く着いた分は待てばよい。
4. 最初の顧客は `t_{i_1} ≥ lo[i_1] ≥ c[0][i_1]` なので、時刻 0 にデポを出て間に合う。
5. A-2 で帰着時刻 `ret_v` が 1 つに決まり、B の (i_k, N+1) の項で `ret_v ≥ t_{i_k} + c[i_k][N+1]`。(N+1, ·) の項で帰着後の顧客もない。ドメインから `ret_v ≤ L[0]`。
6. 時間枠は変数のドメインで保証されている（A-1 の節）。

したがってこれは mTSPTW の実行可能解である。さらに C により、`Z ≥ ret_v ≥`（そのルートを最早開始で辿ったときの実際の帰着時刻）が全車両で成り立つ。つまり **`Z` はそのルートの makespan 以上**になる。

**(2) 実行可能なルート → ペナルティ 0 の割り当て**

逆に、mTSPTW の実行可能解（車両ごとのルートと、最早開始の時刻）が与えられたら、

- 各顧客 i について、担当車両 v と開始時刻 `t_i` の `x[t_i][i][v] = 1`
- 各車両の帰着時刻 `ret_v` の `x[ret_v][N+1][v] = 1`（空車は `ret_v = 0`）
- `Z = max_v ret_v`

とすればよい。A は明らかに満たし、C も `Z` の定め方から満たす。時刻は時間枠内で、デポから直行・直帰しても間に合う範囲なので、ドメイン `[lo, hi]` に入る。B は、隣り合う訪問については実行可能性そのもの。隣り合わない訪問（u の後に w を挟んで y、など）についても、**三角不等式** `c[u][y] ≤ c[u][w] + c[w][y]` が成り立てば `t_y ≥ t_u + c[u][w] + c[w][y] ≥ t_u + c[u][y]` なので満たす。このとき `f = Z = makespan` になる。

**(3) エネルギー最小 = makespan 最小**

(1) と (2) から、ペナルティ 0 の割り当ての中での Z の最小値は、mTSPTW の最適 makespan に等しい。(1) の向きでは `Z ≥ makespan`、(2) の向きでは `Z = makespan` にできるからである。

残るのは「**制約を破った割り当ての方がエネルギーが低くなることはないか**」である。これは重みで保証される。

- A の罰 `(k − 1)²`、B の罰（積の和）、C の罰 `d²`（Z も ret_v も整数なので d は整数）は、どれも**破れば 1 以上の整数**になる。
- したがって、制約を 1 つでも破った割り当てのエネルギーは `Z + (L[0] + 1) × 1 ≥ z_lo + L[0] + 1 > L[0]`。
- 一方、実行可能解が 1 つでもあれば、そのエネルギーは `Z ≤ L[0]`。

よって、実行可能解が存在する限り、**エネルギーの大域最小解は必ず全制約を満たし、その Z は最適 makespan** になる。これが「A・B・C と重み `L[0] + 1` で mTSPTW（min-max）を表せる」ことの根拠である。

#### 厳密さについての注意

(2) で三角不等式を使った。Dumas の距離行列は丸めにより三角不等式がわずかに（最大 5）破れる箇所があり、その場合は実行可能なルートの一部が B で罰せられる（3.2 節）。したがって厳密には、「**三角不等式を満たすインスタンスでは mTSPTW と等価、満たさないインスタンスではごく少しだけ狭い問題**」である。また、B の罰は 0 でない限り必ず 1 以上なので、(1) の向き（得られた解が実行可能であること）は三角不等式によらず常に成り立つ。

## 4. one-hot 版（`time_makespan_multi.py --obj max`）との違い

変数 x と制約 A・B は同じ。違うのは Z の書き方だけである。

| | one-hot 版 | この版（leq） |
|---|---|---|
| Z の表現 | `z[T]`（T ∈ [z_lo, L[0]]）の one-hot。`Z = Σ_T T·z[T]` | ネイティブ整数変数 `Z ∈ [z_lo, L[0]]` 1 個 |
| 追加の 0/1 変数 | `L[0] − z_lo + 1` 個 | 0 個 |
| `ret_v ≤ Z` の書き方 | 禁止ペア `z[T] · x[t][N+1][v]`（t > T）を足す。加えて z の one-hot 制約 | `max(0, ret_v − Z)²` をソルバが直接評価 |
| 違反したときの罰 | 違反の大きさによらず 1 項あたり一定 | 違反量 d に対して d² |

`--build-only` で QUBO の大きさを比べると（2 台、`qubo vars` / `qubo terms`）:

| インスタンス | leq 版 変数 | leq 版 項 | one-hot 版 変数 | one-hot 版 項 |
|---|---:|---:|---:|---:|
| n20w20.001 | 1,476 | 119,801 | 1,510 | 120,956 |
| n60w60.001 | 7,862 | 2,168,437 | 7,906 | 2,170,372 |

差は Z の one-hot 変数（n20w20 なら `408 − 375 + 1 = 34` 個）とそれに付く項だけで、全体から見ればわずかである。モデルの大半は制約 B の衝突項が占める。leq 版の利点は大きさよりも、**Z の値を 1 個の整数として動かせる**（one-hot の「1 を別の位置へ移す」2 ビット反転が要らない）ことと、式が素直なことにある。

## 5. 例: 顧客 3 人・車両 2 台

### 5.1 インスタンス

デポを原点に置き、顧客を次の位置に置く（距離はユークリッド距離を丸めたもの）。

```
          C(3)
          (0,6)
            |
 B(2) ---- 0 ---- A(1)
 (-6,0)  デポ     (6,0)
```

| | 0 | A(1) | B(2) | C(3) |
|---|---:|---:|---:|---:|
| 0 | 0 | 6 | 6 | 6 |
| A(1) | 6 | 0 | 12 | 8 |
| B(2) | 6 | 12 | 0 | 8 |
| C(3) | 6 | 8 | 8 | 0 |

時間枠は顧客すべて `[0, 30]`、デポは `L[0] = 40`。Dumas 形式で書くと次のとおり（1 行目は頂点数 = 顧客数 + 1）。

```
4
0 6 6 6
6 0 12 8
6 12 0 8
6 8 8 0
0 40
0 30
0 30
0 30
```

### 5.2 手で解く

顧客 3 人を 2 台で回すので、どれか 1 台は 2 人以上を回る。2 人回る車両の帰着時刻は

| 2 人の組 | ルート | 帰着 |
|---|---|---:|
| A, C | 0 → A → C → 0 | 6 + 8 + 6 = **20** |
| B, C | 0 → B → C → 0 | 6 + 8 + 6 = **20** |
| A, B | 0 → A → B → 0 | 6 + 12 + 6 = 24 |

1 台で 3 人回るのはもっと遅い（最短でも 6 + 8 + 8 + 6 = 28）。したがって**最適値は 20**。一方、下界は `z_lo = max_i (6 + 6) = 12` で、この例では下界に届かない（2 人回る車両が必ずいるため）。

### 5.3 モデルの大きさ

- 顧客のドメイン: `lo = max(0, 6) = 6`、`hi = min(30, 40 − 6) = 30` → 25 時刻 × 3 人 × 2 台 = 150
- 帰着デポのドメイン: 0..40 → 41 時刻 × 2 台 = 82
- 合計 **x 変数 232 個** + 整数変数 Z（定義域 `[12, 40]`）

### 5.4 ペナルティの具体例

- **衝突（制約 B）**: 車両 0 が A を時刻 6 に始め、C を時刻 10 に始めたとする。`gap(A, C) = 8` なので `6 ≤ 10 < 6 + 8` となり、項 `x[6][1][0] · x[10][3][0]` が 1 になって罰 41 を受ける。C を始められるのは時刻 14 以降。
- **帰着（制約 B）**: 車両 0 が C を時刻 14 に始め、帰着デポ 4 を時刻 18 にしたとする。`gap(C, 4) = 6` なので `14 ≤ 18 < 20` で罰を受ける。帰着は 20 以降。
- **最大値（制約 C）**: 車両 0 の帰着が 20 のときに `Z = 19` にすると、違反量 `d = 1` で罰 `41 × 1² = 41`。エネルギーは `19 + 41 = 60` になり、`Z = 20`（エネルギー 20）より悪い。

## 7. 注意点・限界

- **非最遅車両の帰着変数は緩い**（5.5 節）。帰着時刻の和（`ret_total`）はログに出るが、実際の帰着の和とは一致しないことがある。
- **総移動時間は目的に入っていない**ので、同じ最適値でも走行距離は実行ごとに大きくばらつく（8 節の表）。
- **三角不等式の破れ**により、ごく一部の実行可能ツアーが制約 B で罰せられうる（3.2 節）。
- **時間を 1 単位ずつ刻む**ので、時間枠が広いほど・`L[0]` が大きいほど変数と衝突項が増える（n60w20 → n60w60 で項数が約 3.3 倍）。
